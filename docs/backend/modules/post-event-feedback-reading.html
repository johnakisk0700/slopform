01 / Ο χάρτης

Η ροή περνά από δύο μόνιμα σημεία αναμονής.

Το provider_message_ingress κρατά τι παραλάβαμε. Το message_outbox κρατά τι αποφασίσαμε να στείλουμε. Ανάμεσά τους χτίζουμε τη συνομιλία και επεξεργαζόμαστε την απάντηση.

  1. 01 · HTTPWasender → ingressΈλεγχος webhook, κανονικοποίηση, εγγραφή PostgreSQL, μετά wake-up.
  2. 02 · WORKERΔρομολόγηση & transcriptΣυνομιλία, STOP ή άλλη περίπτωση. Η σειρά παραλαβής ελέγχεται ανά διαδρομή.
  3. 03 · BULLMQ WAKE-UPΑναμονή για να τελειώσει ο γύροςQuiet window 45s από το τελευταίο μήνυμα. Έλεγχος της τρέχουσας εργασίας.
  4. 04 · AI + COMMITΑνάλυση & επιτρεπτή απάντησηSnapshot → AI → επανέλεγχος → αποτελέσματα και outbound intent σε PostgreSQL.
  5. 05 · POSTGRESQL POLLΠαραλαβή από το outboxΟ sender ελέγχει κάθε 1s. Έως 4 claims ανά batch, με σειρά ανά συνομιλία.
  6. 06 · TRANSPORTΆδεια → marker → WasenderΠεριορισμός ρυθμού, τελικός έλεγχος, αποστολή και καταγραφή αποτελέσματος.

Η αρίθμηση δείχνει τη σειρά. Οι βάσεις παραμένουν το σημείο ανάκαμψης όταν μια διεργασία ή ένα προσωρινό wake-up χαθεί.

Queue και polling: γράφουμε πρώτα τη μόνιμη κατάσταση και μετά δημοσιεύουμε συγκεκριμένα BullMQ jobs με IDs και revision. Ο sender έχει ξεχωριστό, απλό poll loop πάνω στο PostgreSQL outbox. Το Redis χρησιμοποιείται επίσης για κοινά όρια ρυθμού. Δεν περιμένει ένας worker ζωντανός να απαντήσει ο χρήστης.

Πριν από την πρώτη στάση: τι κάνει το webhook;

Ο Wasender controller παραδίδει κανονικοποιημένα γεγονότα. Η recordObservedMessageOnce() αποθηκεύει με deduplication και μετά καλεί το materialize wake-up. Αποτυχία enqueue επιστρέφει 503· η εγγραφή μένει pending για επανάληψη ή maintenance.

Τα status updates ακολουθούν τη delivery-status υπηρεσία. Το κύριο παράδειγμα εδώ είναι προσωπικό εισερχόμενο μήνυμα. Ο PostEventFeedbackMaterializationCoordinator.materialize() αποστραγγίζει τα pending με σειρά ανά τηλέφωνο/chat πριν καλέσει τον materializer.

private async materializeOnce(
  input: MaterializeFeedbackIngressInput,
  operation: FeedbackOperationLog,
): Promise<MaterializeFeedbackIngressResult> {
  operation.stage("ingress_load");
  const ingress = await this.ingress.findIngressById(input.ingressId);
  if (!ingress) {
    throw new PostEventFeedbackIngressNotFoundError(input.ingressId);
  }

  if (ingress.processingStatus !== "pending") {
    return { outcome: "already_processed" };
  }

  operation.stage("conversation_match");
  const conversation = ingress.phoneE164
    ? await this.conversations.findOpenByPhone(ingress.phoneE164)
    : undefined;

  if (ingress.direction === "outbound") {
    // Correlate even without an open conversation: a STOP ack is sent to a
    // thread that is already closed.
    operation.stage("outbound");
    const outbound = await this.outbound.materialize(
      ingress,
      conversation,
      input.correlationId,
      operation,
    );
    if (!outbound) {
      operation.stage("unmatched");
      return this.ignoreUnmatched(ingress, input.correlationId, operation);
    }
    return outbound;
  }

  if (conversation) {
    operation.enrich({
      conversationId: conversation._id,
      campaignId: conversation.campaignId,
    });
    operation.stage("inbound");
    return this.inbound.materialize(
      ingress,
      conversation,
      input.correlationId,
      operation,
    );
  }

  // The questionnaire may already have ended; look at the latest closed
  // thread before treating the row as unmatched shared-session traffic.
  const closed = ingress.phoneE164
    ? await this.conversations.findLatestClosedByPhone(ingress.phoneE164)
    : undefined;

  if (closed) {
    operation.enrich({
      conversationId: closed._id,
      campaignId: closed.campaignId,
    });
    operation.stage("post_closure");
    return this.closedIngress.materialize(
      ingress,
      closed,
      input.correlationId,
      operation,
    );
  }

  operation.stage("unmatched");
  return this.ignoreUnmatched(ingress, input.correlationId, operation);
}

PostEventFeedbackExtractor.extractionFlow · γραμμές 92–158 του αρχείου 

private extractionFlow(
  input: ExtractFeedbackInput,
  operation: FeedbackOperationLog,
): Effect.Effect<ExtractFeedbackResult, unknown> {
  return Effect.gen(this, function* () {
    // Skip paid AI work when there is no eligible, unread testimony.
    operation.stage("admit");
    const admitted = yield* attemptPromise(() => this.admission.admit(input));
    if (admitted.kind === "complete") return admitted.result;
    const snapshot = admitted.snapshot;
    operation.enrich({
      campaignId: snapshot.campaign.id,
      conversationId: snapshot.conversation._id,
    });

    // Validate model claims against the snapshot and plan a participant reply.
    operation.stage("plan_turn");
    const turn = yield* attemptPromise(() => this.turns.plan(snapshot));

    // Recheck live state under locks; save paid results and any eligible reply.
    operation.stage("commit_turn");
    const commit = yield* Effect.either(
      attemptPromise(() => this.commits.commit(snapshot, turn)),
    );
    if (Either.isLeft(commit)) {
      if (!(commit.left instanceof FeedbackConversationCapacityError)) {
        return yield* Effect.fail(commit.left);
      }
      // Only a failed commit triggers this separate transaction after rollback.
      operation.stage("capacity_brake");
      return yield* attemptPromise(() =>
        this.capacity.brakeAfterCapacity(snapshot),
      );
    }
    const committed = commit.right;

    // External notifications happen only after the main transaction succeeds.
    if (committed.raisedIncident) {
      operation.stage("notify_operator");
      yield* attemptPromise(() =>
        this.alert.raise({
          conversationId: snapshot.conversation._id,
          campaignId: snapshot.conversation.campaignId,
          reason: "extraction_safety_signal",
          correlationId: input.correlationId,
          detail: [
            ...turn.evidence.validated.safetySignals.map(
              (signal) => `${signal.category}:${signal.recommendedAction}`,
            ),
            ...(turn.evidence.validated.handoff ? ["handoff"] : []),
          ],
        }),
      );
    }
    operation.stage("notify_summary");
    yield* attemptPromise(() =>
      this.summaries.notifyIfLastConversationClosed(
        snapshot.conversation.campaignId,
        input.correlationId,
        committed.state.closedNow,
      ),
    );

    operation.stage("record_outcome");
    return toExtractResult(snapshot, turn, committed);
  });
}

async plan(snapshot: ExtractRunSnapshot): Promise<ExtractPlannedTurn> {
  const operation = new FeedbackOperationLog(this.logger, {
    operation: "extract_plan",
    ...extractionTurnLogContext(snapshot),
  });
  try {
    operation.stage("prepare_context");
    // Assemble the testimony and live facts the AI is allowed to see.
    const prepared = await this.modelContext.prepare(snapshot);
    operation.stage("generate_and_validate");
    // Extract feedback and classify attention; reject unsupported model claims.
    const analyzed = await this.aiTurn.analyze(snapshot, prepared);
    operation.stage("resolve_reply");
    // Choose the reply, apply policy answers, and withhold it if state changed.
    const planned = await this.participantReply.plan(
      snapshot,
      prepared,
      analyzed,
    );
    operation.complete("planned");
    return planned;
  } catch (error) {
    if (
      error instanceof FeedbackConversationExecutionGuardError &&
      error.reason === "authoritative_state_changed"
    ) {
      operation.failed(error, "superseded");
    } else {
      operation.failed(error);
    }
    throw error;
  }
}

async dispatchBatch(
  now = new Date(),
): Promise<FeedbackOutboxDispatchBatchResult> {
  const quarantinedCount = await this.recovery.quarantineExpired(now);
  const terminalCandidates =
    await this.outbox.listTerminalDispatchCandidates();
  const terminalOutboxIds =
    await this.conversations.listCurrentTerminalOutboxIds(terminalCandidates);
  const claims = await this.database.transaction((transaction) =>
    this.outbox.claimDispatchBatch(
      transaction,
      now,
      undefined,
      undefined,
      terminalOutboxIds,
    ),
  );
  // Different conversations use bounded parallel lanes. Claims for one
  // conversation are still serialized as a second line of defence around
  // the repository's cross-replica FIFO eligibility predicate.
  const resultsById = new Map<string, FeedbackOutboxDispatchItemResult>();
  await Promise.all(
    groupClaimsByConversation(claims).map(async (conversationClaims) => {
      for (const claim of conversationClaims) {
        resultsById.set(
          claim.id,
          await this.attempt.dispatchClaimSafely(claim),
        );
      }
    }),
  );
  const items = claims.map((claim) => {
    const result = resultsById.get(claim.id);
    if (!result) {
      throw new Error(`Feedback outbox claim ${claim.id} was not dispatched`);
    }
    return result;
  });

  return { claimedCount: claims.length, quarantinedCount, items };
}

FeedbackDispatchAttemptService.dispatchClaimOnce · γραμμές 89–198 του αρχείου 

private async dispatchClaimOnce(
  claim: FeedbackOutboxClaimedRow,
  operation: FeedbackOperationLog,
): Promise<FeedbackOutboxDispatchItemResult> {
  operation.stage("initial_guard");
  const firstGuard = await this.preparation.guardCurrentState(claim);
  if (firstGuard.state === "settled") {
    return firstGuard.result;
  }

  operation.stage("transcript");
  const recorded = await this.database.transaction((transaction) =>
    this.outboundTranscript.record(transaction, claim, new Date(), claim.id, {
      claimToken: claim.claimToken,
    }),
  );
  if (recorded.outcome === "cancelled") {
    return { outboxId: claim.id, outcome: "cancelled" };
  }
  if (recorded.outcome === "claim_lost") {
    return { outboxId: claim.id, outcome: "claim_lost" };
  }

  // Global pacing may outlive the initial lease as replicas are added. Keep
  // this exact token alive while waiting, then renew once more after the slot
  // before reading state and crossing the no-return marker.
  operation.stage("send_slot");
  const ownsClaimAfterPacing =
    await this.waitForSendSlotWithClaimHeartbeat(claim);
  if (!ownsClaimAfterPacing) {
    return { outboxId: claim.id, outcome: "claim_lost" };
  }

  const transport = new FeedbackOperationLog(this.logger, {
    operation: "dispatch_transport",
    correlationId: claim.id,
    outboxId: claim.id,
    conversationId: claim.conversationId,
    campaignId: claim.campaignId,
    attempt: claim.attemptCount,
  });
  operation.stage("prepare_send");
  const prepared = await this.preparation.prepare(
    claim,
    firstGuard.phoneAtLaunch,
  );
  if (prepared.state === "settled") {
    return prepared.result;
  }
  const { attempting } = prepared;
  const sendInput = {
    to: prepared.phoneAtLaunch,
    text: claim.body,
    outboxId: claim.id,
  };
  if (!attempting) {
    return { outboxId: claim.id, outcome: "claim_lost" };
  }

  // Sync, non-throwing, no await/IO: last reached boundary if the process
  // dies inside the provider call. Child observer keeps a transport failure
  // after the parent moves on to finalize.
  operation.stage("transport");
  transport.stage("transport");
  let result: Awaited<ReturnType<FeedbackTransport["sendText"]>>;
  try {
    // This is deliberately the first fallible operation after the durable
    // send marker. Every state/consent/phone lookup completed above it.
    result = await this.transport.sendText(sendInput);
    transport.complete(
      result.outcome === "accepted"
        ? "accepted"
        : result.outcome === "not-accepted"
          ? "not_accepted"
          : "unknown",
    );
  } catch (error) {
    transport.failed(error);
    operation.stage("finalize_result");
    return this.settlement.markAmbiguous(
      attempting,
      claim.claimToken,
      "unexpected_transport_error",
      error,
    );
  }

  operation.stage("finalize_result");
  if (result.outcome === "accepted") {
    return this.settlement.finalizeAccepted(
      attempting,
      claim.claimToken,
      result,
    );
  }

  if (result.outcome === "not-accepted") {
    return this.settlement.finalizeNotAccepted(
      attempting,
      claim.claimToken,
      result,
    );
  }

  return this.settlement.finalizeUnknown(
    attempting,
    claim.claimToken,
    result,
  );
}

03 / Τέσσερις διαδρομές

Ακολούθησε τι αλλάζει όταν χαλάσει η ευθεία.

Α / Κανονική απάντηση

«Πέρασα ωραία, 5»

Η μαρτυρία μπαίνει στο transcript, ενημερώνει τη due εργασία και περιμένει το quiet window. Το AI αναλύει το snapshot. Το commit αποθηκεύει αποτελέσματα και την επιτρεπτή απάντηση στο outbox.

Πού το ακολουθείς

InboundMessage.materialize → extractionFlow → commit / commitOn → dispatchClaimOnce.

Να εξηγήσεις: γιατί το AI επιστρέφει ένα σχέδιο και η εξωτερική αποστολή γίνεται σε άλλη φάση.

Β / STOP

«ΣΤΟΠ»

Ο υπάρχων matcher ενεργοποιείται πριν από AI. Κλείσιμο, ανάκληση opt-in, ακύρωση queued μηνυμάτων, ακριβές ACK, audit και ολοκλήρωση ingress ανήκουν στην ίδια συναλλαγή.

Πού το ακολουθείς

matchesPostEventFeedbackStopCommand → FeedbackStopService.apply → guardCurrentState.

Μόνο το ακριβές ACK του lifecycle περνά την εξαίρεση consent/terminal. STOP εξακολουθεί να εφαρμόζεται και μετά το κλείσιμο. Αν το transcript είναι γεμάτο, η ανάκληση συναίνεσης εξακολουθεί να ισχύει· ACK που δεν χωρά μπορεί να ακυρωθεί.

Γ / Νεότερο μήνυμα

«Όχι, τελικά 4» ενώ δουλεύει το AI

Το πρώτο snapshot μπορεί να έχει παλιώσει. Ελέγχουμε ξανά τόσο στο commit όσο και πριν από την αποστολή. Ανάλογα με το σημείο της αλλαγής, κρατάμε επιτρεπτά αποτελέσματα που ήδη πληρώσαμε και αποσύρουμε την ξεπερασμένη απάντηση, ή η εκτέλεση βγαίνει superseded.

Πού το ακολουθείς

FeedbackParticipantReplyPlanner.plan → commitOn / persistOn → ordinaryExtractionReplyStaleReason.

Το dispatch_context κρατά τις γενιές του αρχικού snapshot. Ελέγχονται και νεότερα durable ingress που ακόμη δεν μπήκαν στο transcript. Το quiet window δεν ακυρώνει μια ήδη ενεργή κλήση AI.

Δ / Αβέβαιη αποστολή

Ο provider δεν απάντησε καθαρά

Αφού καταγραφεί attempting, μπορεί να έχει γίνει αποστολή. Unknown ή απρόβλεπτο transport error οδηγεί σε ambiguous και χειρισμό από άνθρωπο. Αυτό το μήνυμα δεν ξαναστέλνεται αυτόματα.

Πού το ακολουθείς

dispatchClaimOnce → markAmbiguous / parkUncertainDelivery. Αν πεθάνει η διεργασία, η quarantineExpired αναλαμβάνει την εκκρεμή προσπάθεια.

Ρητή απόρριψη γίνεται failed στην τωρινή πολιτική, ακόμη και σε rate limit. Αποδοχή γίνεται sent· μεταγενέστερα delivery events μπορούν να δείξουν delivered/read. Ένα webhook παρατήρησης μπορεί επίσης να αποδείξει ότι ένα ambiguous μήνυμα στάλθηκε.

04 / Γιατί υπάρχουν τα όρια

Το μέγεθος εξηγείται από τα ενδιάμεσα ενδεχόμενα.

Η ευθεία «παραλαβή → AI → απάντηση» είναι μικρή. Ο επιπλέον κώδικας αντιμετωπίζει διπλή παραλαβή, μηνύματα που φτάνουν κατά τη διάρκεια του AI, STOP, takeover, γεμάτο transcript και αβέβαιο provider. Κάθε μηχανισμός χρειάζεται να εξηγεί ποιο από αυτά προστατεύει. Αυτό δεν δικαιολογεί από μόνο του κάθε μεγάλη κλάση.

Έννοια Τι σημαίνει εδώ Τι πρόβλημα αποφεύγει
Ingress Μόνιμη εγγραφή μιας παρατήρησης από τον provider. Χαμένο μήνυμα ή διπλό transcript μετά από redelivery.
Work revision Η έκδοση της προγραμματισμένης εργασίας της συνομιλίας. Παλιό job που εκτελεί απόφαση για προηγούμενο γύρο.
Claim / fence Προσωρινή ιδιοκτησία εργασίας και token/epoch που ελέγχεται όταν γράφουμε. Worker που έχασε την ιδιοκτησία αλλά συνεχίζει να αλλάζει κατάσταση.
Outbox intent Το σώμα και τα στοιχεία που στηρίζουν την απόφαση αποστολής. Αποστολή χωρίς committed απόφαση ή με ξεπερασμένη άδεια.
Attempting Μόνιμο marker ότι περνάμε το όριο προς τον provider. Τυφλό retry μετά από crash που μπορεί να διπλοστείλει το μήνυμα.

Πού είναι οι transactions;

Οι services κρατούν την ολόκληρη πράξη και δίνουν το ίδιο tx στα repositories. Η applyPending κρατά μαζί τον έλεγχο replay και το κλείδωμα ingress. Το extraction commit και η τελική προετοιμασία send έχουν τις δικές τους σύντομες συναλλαγές.

Κλήσεις AI και WhatsApp γίνονται αφού έχουν λήξει οι αντίστοιχες συναλλαγές. Το database lock προστατεύει την απόφαση· δεν κρατιέται πάνω από το δίκτυο.

Έχουμε WhatsApp adapter;

Ναι: το FeedbackTransport.sendText δίνει accepted, not-accepted ή unknown. Η WasenderFeedbackTransport μεταφράζει τον provider σε αυτό το συμβόλαιο.

Υπάρχουν επίσης simulated και disabled adapters. Η επιλογή adapter μένει στο worker module. Η απόφαση για την κατάσταση του outbox ανήκει στον dispatcher.

Τι κάνει το Effect;

Η extractionFlow χρησιμοποιεί Effect.gen για τα τοπικά βήματα. Οι attemptPromise / runWithOriginalError διατηρούν τα αρχικά σφάλματα στο όριο Promise.

Nest για DI, BullMQ για jobs/retries. Χωρίς Tags, Context ή Layers. Δες το ADR 0017 και την γέφυρα Promise όταν φτάσεις σε εκείνη τη μέθοδο.

Τι γράφει ο logger;

Η FeedbackOperationLog παρατηρεί operation, stage, IDs και outcome. Αποτυχία του log sink δεν αλλάζει την επιχειρησιακή απόφαση.

Audit και outbound history είναι ξεχωριστές, transactional εγγραφές. Η άδεια send βασίζεται στο dispatch_context. Stage «started» δείχνει πού μπήκε η εκτέλεση· δεν αποτελεί απόδειξη commit.

Για την αποθήκευση: η campaign συνομιλία βρίσκεται σε PostgreSQL μαζί με την επιχειρησιακή της κατάσταση. Τα admin Assistant threads παραμένουν σε MongoDB. Αυτή η αλλαγή αφαίρεσε το cross-database sync από το feedback. Το ADR 0015 περιγράφει τον διαχωρισμό.

05 / Να μπορείς να το εξηγήσεις

Πέντε ερωτήσεις για τη συζήτησή μας.

Προσπάθησε πρώτα με δικά σου λόγια. Έπειτα άνοιξε το σημείο αναφοράς και γύρνα στη σχετική μέθοδο.

  1. Γιατί δεν καλούμε το AI μέσα στο webhook;
    Σημείο αναφοράς

    Το HTTP παραλαμβάνει και αποθηκεύει γρήγορα. Το worker περιμένει τον γύρο, φορτώνει τρέχουσα κατάσταση και χειρίζεται την εκτέλεση. Αν χαθεί το enqueue, το durable ingress επιτρέπει ανάκαμψη.

  2. Γιατί ελέγχουμε ξανά μετά το AI;
    Σημείο αναφοράς

    Το AI δουλεύει σε snapshot. Στο μεταξύ μπορεί να ήρθε νέα μαρτυρία, STOP, takeover ή pause/resume. Η εγκυρότητα των εξαγόμενων στοιχείων και η άδεια να σταλεί συγκεκριμένη απάντηση είναι διαφορετικές αποφάσεις.

  3. Πότε επιτρέπεται retry και πότε φοβόμαστε διπλή αποστολή;
    Σημείο αναφοράς

    Πριν από το marker μια ληγμένη claimed προσπάθεια μπορεί να ανακτηθεί. Μετά το attempting ο provider ίσως έχει δεχτεί. Unknown σημαίνει ambiguous και χρειάζεται συμφιλίωση με παρατήρηση ή άνθρωπο. Δεν υποσχόμαστε exactly-once αποστολή μέσω δικτύου.

  4. Γιατί δύο βάσεις και πού τελειώνει η επέκταση feedback;
    Σημείο αναφοράς

    Η σημερινή επέκταση έχει campaigns, μαρτυρία συμμετέχοντα, structured αποτελέσματα, συναίνεση, έλεγχο γύρων και outbox σε PostgreSQL. Ο ξεχωριστός admin Assistant διατηρεί τα Mongo threads του. Η αφήγηση του feedback δεν απαιτεί να περάσουμε από εκείνο το storage.

  5. Πώς προσθέτεις μία νέα περίπτωση χωρίς να μπερδέψεις τη ροή;
    Σημείο αναφοράς

    Βρίσκεις πρώτα τον ιδιοκτήτη της απόφασης: transport normalization, ingress handler, καθαρή policy, AI planning ή dispatch. Ορίζεις input/outcome και τι πρέπει να είναι atomic. Προσθέτεις τη συμπεριφορά εκεί, με focused κάλυψη της νέας περίπτωσης, κρατώντας τον coordinator ευανάγνωστο.

06 / Τα επόμενα κεφάλαια

Ο βασικός γύρος είναι το πρώτο σταθερό σημείο ανάγνωσης.

Αυτός ο οδηγός καλύπτει τη διαδρομή εισερχόμενου → AI → αποστολής. Το υπόλοιπο module έχει ακόμη δουλειά καθαρογραφής και μελέτης. Το τρέχον πλάνο κρατά την πρόοδο.

Μετά τον βασικό γύρο Τι θα διαβάσουμε / βελτιώσουμε
Staff actions · 1.317 γραμμές Takeover, resume, close, ανθρώπινα μηνύματα και διορθώσεις αποτελεσμάτων.
Campaign summary · 1.076 γραμμές Claim, context, generation, persistence και ειδοποίηση.
Outbox repository / Conversation repository 1.453 / 1.387 γραμμές. Τα πραγματικά SQL και οι εγγυήσεις locks, CAS και storage. Απομένει έλεγχος συνοχής των ευθυνών.
Tests & harnesses στο vibes/ Παραμένουν ενεργά. Το extraction spec των 4.543 γραμμών θέλει οργάνωση fixtures/περιπτώσεων μετά τη σταθεροποίηση των μηχανισμών.

Για απορίες σε συγκεκριμένο σενάριο: κατάλογος συμπεριφορών. Για συμβόλαια και περιορισμούς: module, queues και runtime / logs.

Τα αποσπάσματα και οι μετρήσεις αντιστοιχούν στο checkpoint αυτού του οδηγού. Το πλήρες pnpm check πέρασε. Το ανεξάρτητο review του Astra δεν βρήκε διορθώσεις στο συγκεκριμένο split. Οι relative σύνδεσμοι δείχνουν αρχεία μέσα στο checkout· αν κρατήσεις μόνο το HTML, τα ενσωματωμένα αποσπάσματα εξακολουθούν να διαβάζονται.

Ο οδηγός είναι βοήθημα μελέτης. Κώδικας, tests και τα ενημερωμένα module contracts είναι η λειτουργική αναφορά. Οι χρόνοι, οι γενιές και οι επιπλέον έλεγχοι αναλύονται στο δεύτερο πέρασμα.
